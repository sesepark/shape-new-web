# SHAPE Web 설계 기록

[프로젝트 소개](../README.md)

## 기록해 둘 만한 설계

이 프로젝트에서 가장 많은 고민이 들어간 부분은 **전부 무료 티어 위에서 돌아가게 만드는 것**
이었음. `docs/free-tier-deployment.md`에 근거와 실측을 적어 두었고, 요약하면 이렇다.

- **2단 캐시의 창 길이를 맞췄음.** 앞은 Next.js Data Cache, 뒤는 백엔드 응답 캐시임. Neon 요금은
  질의 횟수가 아니라 *깨어 있는 시간*이라, 두 창이 어긋나면 데이터베이스를 깨우는 시점이 흩어져
  이득이 사라짐. 대신 정확히 같은 순간에 만료시키지는 않음(30초 안에서 분산) — 그 순간이 곧
  부하가 되기 때문임.
- **같은 창구는 한 번만 채움**(`cache.lock_for`). Vercel이 여러 지역에서 동시에 재검증하는 탓에,
  묶지 않으면 동시 8건이 질의 24건이 되는 것을 실측했음. 연결이 셋뿐인 무료 인스턴스에서는
  그대로 줄서기가 됨.
- **캐시는 허용 목록 방식임.** 세션 쿠키가 실린 요청은 공개 읽기라도 `private, no-store`로
  내려감. 같은 주소인데 보는 사람에 따라 `canEdit`이 달라지는 응답이 있어, 남의 화면에 수정
  버튼이 뜨는 사고를 구조적으로 막았음.
- **레이트 리밋을 로그인 회원은 계정별로, 나머지는 주소별로 셈.** 학교 Wi-Fi처럼 여러 명이 한
  주소를 나눠 쓰는 곳에서 서로의 한도를 깎지 않게 하기 위해서임.
- **운영 상수를 코드에서 데이터베이스로 내렸음.** 자동 확정 시각·운영진 재알림 시각·사용 시작
  유예는 원래 파이썬 상수였고, 그래서 "자동 확정을 한 시간에서 두 시간으로" 같은 결정에도 코드
  수정과 배포가 필요했음. 지금은 행이 하나뿐인 `reservation_policy` 표에 있고 운영진이 직접 바꿈.
  대신 그 값이 바뀌는 순간 **부원 화면의 안내 문구가 통째로 옛말이 되므로** 이 응답만 캐시를 짧게
  두었음.
- **비어 있는 시간은 시계가 확정함.** 시작까지 정해진 시간 안으로 들어왔고 같은 호기·같은 시간에
  다투는 신청이 없으면, 운영진을 기다리지 않고 자동으로 확정됨. 그리고 **내 신청이 언제 저절로
  확정되는지를 화면이 먼저 말함** — 규칙만 설명하고 내 경우가 어느 쪽인지 말해 주지 않으면 부원은
  결국 운영진에게 직접 물어보게 되기 때문임.
- **때가 된 알림을 크론 없이 보냄.** 무료 티어에는 상시 워커가 없으므로, 로그인한 회원의 요청에
  얹어 3분마다 한 번씩만 확인함. 회원 요청은 어차피 `/auth/me`로 데이터베이스를 여니 이미 깨어
  있는 Neon을 쓰는 셈이라 값이 들지 않음.
- **목록을 돌려주는 창구에는 모두 개수 상한과 커서 페이지네이션을 두었음.** 상한 없는 조회는
  학기가 쌓이는 만큼 응답이 무거워지기 때문임.
- **모바일을 먼저 봄.** 눈대중이 맞지 않아서, 32:9 울트라와이드부터 320px 휴대폰까지 14가지 폭을
  훑는 Playwright 감사 스크립트(`frontend/scripts/responsive-audit.mjs`)를 만들어 넘침·잘림·줄바꿈
  붕괴를 자동으로 찾게 했음.

구조 전체는 [`docs/architecture.md`](../docs/architecture.md) 한 장에 정리해 두었음.
